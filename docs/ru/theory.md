# Теория

[English version](../en/theory.md) · [README](../../README.ru.md)

Страница объясняет четыре идеи статьи и то, как их использует код. Формулы
соответствуют документу `idei_gruppy_li_martingaly.md`. Полная теория — в
документе, здесь только то, на что опирается код.

## Задача простыми словами

Распределитель перераспределяет память между виртуальными машинами баллунингом.
Каждое перераспределение стоит времени. Спрос проверяется через интервалы.
Текущее правило задаёт следующий интервал по числу перераспределений за пять
последних проверок и по тому же числу задаёт режим. Оба порога подобраны вручную.

Библиотека заменяет оба решения методами с обоснованием:

| Решение | Текущее правило | Замена |
|---|---|---|
| интервал до следующей проверки | таблица по `S` (5 битов) | `Δt = −ln(1 − p*)/λ̂` или `Δt = √(2C₁/(λ̂C₂))` |
| режим | `S ≥ 3` | детектор Ширяева–Робертса по решениям |
| доли памяти | не задавались | координаты clr с ограничениями и зоной δ |

## Идея 1. Доли памяти на симплексе

Доли `w` пула положительны и в сумме дают единицу. Операция
`(w ⊕ p)_i = w_i p_i / Σ_j w_j p_j` (функция `perturb`) — групповая операция,
нейтральный элемент — равные доли. Логарифм группы — центрированное
логарифмическое преобразование, экспонента — softmax:

    z_i = ln w_i − среднее(ln w),      w = softmax(z)

В этих координатах шаг не имеет ограничений, а softmax всегда даёт корректные
доли. Расстояние Эйчисона `d = ‖clr(w₁) − clr(w₂)‖` (функция `aitchison_distance`)
не зависит от общего объёма памяти. Оно измеряет относительное изменение: рост
доли с 1 % до 2 % даёт `d ≈ 0,50`, с 40 % до 41 % — только `d ≈ 0,03`. Поэтому
зона нечувствительности `δ` — расстояние в координатах clr, её надо калибровать
по трассам.

Группа коммутативна, геометрия по сути совпадает с `ℝⁿ⁻¹`. Язык групп Ли
обосновывает метод и делает формулы короче. Новых результатов он не даёт.

## Идея 2. Интервал из масштабной инвариантности и затрат

Если умножить все объёмы памяти и все единицы времени на одно число, правило
должно дать тот же относительный результат. Поэтому правило строится из
безразмерных величин и модели затрат.

* **Правило А**: `Δt = −ln(1 − p*) / λ̂`. При пуассоновской модели с интенсивностью `λ`
  `P(N(Δt) ≥ 1) = 1 − e^{−λΔt} = p*` даёт этот интервал. Линейная форма
  `Δt = p*/λ̂` — первый член разложения Тейлора. Она короче: при `p* = 0,3` точный
  интервал примерно на 19 % длиннее. Параметр `formula="linear"` выбирает её, а
  `scale` умножает интервал. При наивной оценке `N/T` доля ходов в стационарном
  режиме около 0,36, а не `p*`. Линейная форма сохраняет долю `p*`.
  Параметр `estimator="naive"` выбирает `N/T`; по умолчанию стоит оценка debiased,
  которая сочетается с точной формой (см. раздел о сочетаниях).
  Пуассоновская модель для этого не нужна.
* **Правило Б**: `Δt = √(2C₁ / (λ̂C₂))`. Минимизирует скорость затрат
  `J(Δt) = C₁/Δt + λC₂Δt/2`, где `C₁` — стоимость проверки, `C₂` — стоимость
  секунды задержки. Важно только отношение `C₁/C₂`. Точный оптимум
  Барлоу, Ханта и Прошана решает `e^{λx} − 1 − λx = λC₁/C₂` (функция `exact_interval`).
* **Правило В**: `Δt = δ/v`, где `v` — дрейф долей в расстоянии Эйчисона.

Все правила ограничены отрезком `[1 с, 10 с]`, как текущая таблица.

## Правило А: четыре сочетания формы и оценки

У правила два выбора. Форма — `exact` (`g = −ln(1 − p*)`, по умолчанию) или
`linear` (`g = p*`). Оценка интенсивности — `debiased` (по умолчанию) или `naive`
(`N/T`). Оценка задаётся параметром `estimator` в `ControllerConfig`,
`RegimeController` и `analyze --estimator`. При постоянной истинной `λ` и интервале
`Δt = g/λ̂` стационарный режим такой (`q` — доля ходов, `G = scale · g(p*)`):

| сочетание | доля `q` | `λΔt` |
|---|---|---|
| exact, debiased (по умолчанию) | `p*` | `−ln(1 − p*)` |
| linear, naive | `p*` | `−ln(1 − p*)` |
| exact, naive | `−ln(1 − p*)` | `−ln(1 − G)` |
| linear, debiased | `1 − e^{−p*}` | `p*` |

Первые два сочетания дают цель `p*`. Функция `steady_state_share` возвращает эти
значения. Таблица ниже сравнивает их с моделированием на конфигурации

аналитики ожидаемы.

## Идея 3. Интенсивность решений с забыванием в реальном времени

Сумма пяти битов не меняется при перестановках, поэтому она не учитывает порядок
событий. Её математическое ожидание зависит от интервала: при `λ = 0,05 1/с` оно
около 0,24 при `Δt = 1 с` и около 1,97 при `Δt = 10 с`. Сумма задаёт интервал,
а интервал меняет сумму, поэтому режим переключается часто даже при постоянной
нагрузке. Точное число переключений даёт `flicker_stats`: 57 в час при
`λ = 0,05 1/с` и 137 при `λ = 0,1 1/с` для условной таблицы документа.

Замена — оценка с экспоненциальным забыванием в реальном времени:

    N_k = e^{−Δt_k/τ} N_{k−1} + b_k
    T_k = e^{−Δt_k/τ} T_{k−1} + Δt_k
    λ̂_k = N_k / T_k

Экспоненциальные веса — единственные, которые согласованы с линейной рекурсией
с одним числом при любых интервалах (функциональное уравнение Коши). Наивное
отношение занижено при большом `λΔt`. Его относительное смещение
`(1 − e^{−x})/x − 1`, где `x = λΔt`: −2,5 % при `Δt = 1 с`, −11,5 % при `5 с`,
−21 % при `10 с` для `λ = 0,05 1/с`. Оценка с поправкой — `−ln(1 − p̂)/Δ̄`, где
`p̂ = N/K` — доля перераспределений, `Δ̄ = T/K` — средний интервал. Она точна при
постоянном интервале (`ForgettingRate.debiased`).

## Идея 4. Мартингальный детектор режима

При модели `P(b_k = 1 | прошлое) = 1 − e^{−λΔt_k}` множитель отношения
правдоподобия между `λ = κλ₀` и `λ = λ₀` равен

    f_k = (1 − e^{−κλ₀Δt_k}) / (1 − e^{−λ₀Δt_k})   если b_k = 1
    f_k = e^{−(κ−1)λ₀Δt_k}                          если b_k = 0

При нулевой гипотезе его условное математическое ожидание равно 1. Поэтому
`Λ_n = f_1 ⋯ f_n` — мартингал, и это верно, даже когда интервалы выбраны по
прошлым данным. Библиотека использует статистику Ширяева–Робертса с весом времени:

    R_k = (Δt_k + R_{k−1}) f_k

Среднее время до ложной тревоги не меньше порога `A` в секундах (Pollak, 1985,
теорема об остановке). CUSUM `S_k = max(0, S_{k−1} + ln f_k)` с `h = ln A` даёт
такую же гарантию и консервативнее. Работают два детектора: рост с `κ > 1` и
спад с `κ < 1`.

Три оговорки.

1. **Модель.** Гарантия верна при `P(b = 1) = 1 − e^{−λΔt}`, то есть без переноса
   нерешённой потребности на следующую проверку. `trosna-regime-control analyze`
   проверяет это функцией `fit_cloglog`: наклон при `ln Δt` должен быть близок к 1,
   коэффициент при предыдущем бите — близок к 0. Перенос 0,4 модель не проходит.
2. **Базовый уровень `λ₀`.** Он оценён по тем же данным, поэтому гарантия
   приближённая. Контроллер берёт верхнюю границу `λ₀⁺` для детектора роста и
   нижнюю `λ₀⁻` для детектора спада. Границы односторонние, на уровне `confidence`
   (по умолчанию 0,95), или на `z` стандартных отклонений, если задано `z`. Более
   высокий уровень даёт большее `λ₀⁺`, меньшее `λ₀⁻` и меньше тревог. Уровень —
   параметр контроллера и `ForgettingRate`, а не константа. Для роста нулевая гипотеза — `λ ≤ λ₀`,
   для спада — `λ ≥ λ₀`, и математическое ожидание множителя этим условиям
   соответствует (проверено численно).
3. **Скорость.** Граница Лордена `ln(ARL)/I` асимптотическая. При умеренном ARL
   реальная задержка меньше, иногда вдвое. Её измеряют функцией `run_lengths`
   для выбранного порога.

## Как всё работает вместе: контроллер

`RegimeController` получает проверку `(t, b)` и делает следующее:

1. учитывает проверку: обновляет `λ̂` с реальным интервалом `Δt = t − t_prev`;
2. передаёт проверку детекторам. После тревоги режим нестационарный на `hold_s`, интервал
   минимальный (1 с), базовые уровни сбрасываются на быструю оценку;
3. в стационарном режиме интервал берётся по правилу А или Б.

Гарантии относятся к детектору. Правила А и Б — это выбор интервала, а не
утверждение об оптимальной политике при меняющемся спросе.

## Что не утверждается

* Групповая структура коммутативна и не добавляет новых теорем.
* Оптимальность CUSUM и процедуры Ширяева–Робертса доказана для независимых
  наблюдений с постоянным шагом. Для адаптивных интервалов гарантия — среднее
  время до ложной тревоги, а не оптимальность.
* Метод не оценивает рост памяти. Это задача `azarovo-martingale`.
